## GOAL
`api-lib`'s `client` preset and its `generator`/`additionalProperties` overrides can disagree (e.g. `client=angular, generator=typescript-axios` still applies Angular's `ngVersion=17.0.0,providedInRoot=true` to a `typescript-axios` build). Rather than patching the merge precedence in `api-lib` itself, remove the `client` preset concept from `api-lib` entirely: `api-lib.generator` becomes a required field with no default and no preset resolution, so a mismatch is structurally impossible there. The `client` convenience (framework presets for angular/react/vue/node) moves to live only in `init`, which already prompts for `client` for its one-shot bootstrap and forwards it to `apiLibGenerator` — `init` now resolves `client` into a concrete `generator`/`additionalProperties` pair itself before calling `apiLibGenerator`, instead of forwarding an ambiguous `client` field down. **BREAKING**: `api-lib`'s `--client` option is removed; direct `api-lib` callers must now always pass `--generator` explicitly. The documented quick-start (`nx generate ...:api-lib ... --client=react ...`) and the README's "Client presets" section describe a workflow that no longer exists at the `api-lib` level and must be rewritten.

## CONSTRAINTS
- generator-scope: `init` and `api-lib` both change (`init/generator.ts`, `init/client-presets.ts` new, `api-lib/generator.ts`, `api-lib/schema.json`). `api-spec` and the `generate-api-lib-sources` executor are untouched.
- no-generator-override-in-init: `init`'s `client` prompt stays a one-shot convenience with no accompanying `generator` override option — that combination is out of scope. Anyone needing a specific generator uses `api-lib` directly with an explicit `--generator`.
- preserve-custom-default: `client: 'custom'` (init's default) still resolves to `generator: 'typescript-fetch'` with no `additionalProperties` — the bootstrap's externally-visible default output is unchanged.
- tsconfig-untouched: this change does not touch `tsconfig.base.json` path-mapping logic.
- conventional-commit-breaking: the `api-lib` schema change removing `client` and requiring `generator` is a breaking change to a published option — the implementing commit(s) must use `feat!:`/`BREAKING CHANGE:` per commitlint/`nx release` conventions, not a plain `fix:`.
- e2e-not-required: `nx-plugin-openapi-e2e`'s happy-path suite doesn't reference `--client` on `api-lib` today (grepped, no hits) and doesn't need new coverage; unit tests in `init` and `api-lib` are sufficient.
